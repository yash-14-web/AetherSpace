Disaster Recovery & Infrastructure Runbook

1. Application vs PostgreSQL PITR

This workbook system operates at the application entity level, enabling cross-workspace migration, granular recovery, and audit trails. Physical disaster recovery is separately managed via Supabase PostgreSQL Point-in-Time Recovery (PITR).

2. Chat Exclusion Policy

Team Chat and direct messages are intentionally excluded from Excel backups to safeguard member privacy, prevent token leaks, and maintain lean backup sizes suitable for rapid workspace migrations.

3. Supabase Storage Integrity

StoredFile rows record canonical Supabase storage paths and metadata. After performing a restore, use the Storage & Files console to execute a storage sync audit.
